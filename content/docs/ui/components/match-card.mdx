## With odds

Pass `odds` to render an odds row using the same options as
[Odds Selector](/docs/ui/components/odds-selector) — options are labeled
"1" / "X" / "2" here rather than team names, since the odds row has to stay
narrow. Set `oddsPosition="right"` to keep it beside the match instead of
below — a single wide row, suited to desktop/wide layouts (shown second
below, on a live match to show off the row variant with real live state —
score, elapsed clock, red cards). This example subscribes to live odds too
(Business tier) — if none are available for a given match, that card's row
just doesn't render.

### Selecting an option

Odds selection is controlled, the same pattern as
[Odds Selector](/docs/ui/components/odds-selector#props) itself — Match
Card has no internal state for it. Track the selected id yourself and pass
it back in:

```tsx
const [selectedOddsId, setSelectedOddsId] = useState<string>()

<MatchCard
  {...matchCardProps}
  selectedOddsId={selectedOddsId}
  onSelectOdds={setSelectedOddsId}
/>
```

Omit both and the row stays fully clickable, but nothing will ever render
as selected — there's no fallback state to fall back to. Pressing the
already-selected option deselects it — `onSelectOdds` fires with
`undefined` — so `setSelectedOddsId` above is really all the logic this
needs; there's no toggle to write yourself. The example above tracks
`selectedOddsId` independently per card, since each is showing a different
match.

## Loading

Pass `loading` on its own — no other prop is needed — to render a skeleton
with the exact same dimensions, so nothing shifts once real data arrives.
Both examples above already use this while their subscription connects.

## Use with the Mr. Doge SDK

MatchCard takes plain props, so it works with any data source. Mapping a
real `matches.get()` (plus a market from `odds.list()`) response onto those
props is a small, pure function — type-checked against the actual SDK
response shape, so a schema change fails to compile instead of silently
going stale:

```tsx
import type { MatchDetail, Market } from "@mrdoge/protocol"
import type { MatchCardDataProps, MatchCardOdds } from "@/components/match-card"
import type { LiveIndicatorStatus } from "@/components/live-indicator"
import type { OddsOption, OddsMovement } from "@/components/odds-selector"

// match.status is authoritative and always fresh. Clock.state adds
// paused/intermission/interrupted, but comes from the live-stats feed,
// which can stop updating once a match ends — so match.status decides
// the coarse bucket first; clock.state only refines *within* "live".
function toLiveIndicatorStatus(match: MatchDetail): LiveIndicatorStatus {
  if (match.status === "upcoming") return "scheduled"
  if (match.status === "completed") return "finished"
  return match.stats?.clock?.state ?? "live"
}

// Outcome order (1/X/2 left-to-right, Over before Under, ...) is decided
// server-side — the SDK gateway orders every market's betItems before
// they're ever returned, so there's nothing to sort here.
//
// Match Card's odds row is narrow, so it asks for "code" (1/X/2) instead
// of the default team-name caption — short, and never needs truncating.
function toOddsOptions(
  market?: Market,
  {
    labelFrom = "caption",
    movementById,
  }: {
    labelFrom?: "caption" | "code"
    /** From useOddsMovement(market) — id -> "up" | "down" since the previous snapshot. */
    movementById?: Record<string, OddsMovement>
  } = {}
): OddsOption[] {
  if (!market) return []
  return market.betItems.map((item) => ({
    id: item.id,
    label: labelFrom === "code" ? item.code : (item.caption ?? item.code),
    price: item.price.toFixed(2),
    suspended: !item.isAvailable,
    movement: movementById?.[item.id],
  }))
}

// Market.betType is a raw sysname on the wire (e.g. "SOCCER_MATCH_RESULT"),
// not a display label — a real name lookup table is out of scope here, so
// this falls back to a light cleanup (underscores to spaces, title case)
// rather than the raw sysname or a fabricated name.
function toMarketLabel(betType: string): string {
  return betType
    .toLowerCase()
    .split("_")
    .map((word) => word[0].toUpperCase() + word.slice(1))
    .join(" ")
}

function toMatchCardOdds(
  market?: Market,
  movementById?: Record<string, OddsMovement>
): MatchCardOdds | undefined {
  if (!market) return undefined
  return {
    market: toMarketLabel(market.betType),
    options: toOddsOptions(market, { labelFrom: "code", movementById }),
  }
}

// Public, unauthenticated, cached CDN — not part of the Team shape itself.
// See /docs/reference/images.
function teamLogoUrl(teamId: number) {
  return `https://api.mrdoge.co/images/teams/${teamId}.png`
}

function matchToMatchCardProps(
  match: MatchDetail,
  market?: Market,
  movementById?: Record<string, OddsMovement>,
): MatchCardDataProps {
  // Red cards are soccer-specific — MatchStats is a discriminated union per
  // sport, so narrow before reading homeRedCards/awayRedCards.
  const stats = match.stats?.sport === "soccer" ? match.stats : undefined

  return {
    status: toLiveIndicatorStatus(match),
    kickoff: match.startTime,
    // Only meaningful while in progress — once completed, drop the frozen
    // clock display and let LiveIndicator show its own "FT" label.
    elapsed: match.status === "live" ? (match.stats?.clock?.display ?? undefined) : undefined,
    home: {
      name: match.homeTeam.name,
      logoUrl: teamLogoUrl(match.homeTeam.id),
      redCards: stats?.homeRedCards,
    },
    away: {
      name: match.awayTeam.name,
      logoUrl: teamLogoUrl(match.awayTeam.id),
      redCards: stats?.awayRedCards,
    },
    homeScore: match.stats?.homeScore,
    awayScore: match.stats?.awayScore,
    odds: toMatchCardOdds(market, movementById),
  }
}
```

`movementById` is optional throughout — pass
[useOddsMovement](/docs/ui/hooks/use-odds-movement)`(market)`'s result to
show up/down indicators on options as prices change, or omit it entirely
and options just render without one.

Both examples above render through exactly this pattern — they're wired to
a real, live `matches.subscribe()` connection (see the example source via
"View Code"), and this same function maps each push straight into
`MatchCard`'s props.

### MatchCardSkeleton

`<MatchCard loading />` renders this internally, but it's also exported on
its own — `import { MatchCardSkeleton } from "@/components/match-card"` —
for a loading list of several cards before any of them have data yet.
Takes only `className`.
