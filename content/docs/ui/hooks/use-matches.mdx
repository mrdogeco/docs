This is the resolver behind [Bet Slip](/docs/ui/components/bet-slip)'s
default example. `useTrendingMatches` only covers today's most-viewed
matches — a real but narrow slice, and one that's sometimes empty (e.g.
nothing upcoming happens to be trending right now). `useMatches` wraps
the plain `matches.list()` listing instead, so a demo like this one that
just needs *some* real upcoming match keeps working regardless:

## Usage

```tsx
import { useMatches } from "@/hooks/use-matches"

function UpcomingMatches() {
  const matches = useMatches({ sports: ["soccer"], status: ["upcoming"], limit: 20 })

  if (matches === undefined) return <p>Loading…</p>
  if (matches === null) return <p>Couldn't load matches.</p>

  return matches.map((m) => <p key={m.id}>{m.homeTeam.name} vs {m.awayTeam.name}</p>)
}
```

Takes a single options object, like every real SDK method it wraps
(`matches.list(params)`) — not positional arguments.

## Returns

`Match[] | null | undefined` — `undefined` while the request is in flight,
`null` if it failed (no fallback data), otherwise the list. One-shot: this
doesn't push live updates the way `useLiveMatch`/`useLiveOdds` do — call it
again (or remount) to refresh.

## Composing with useMatch

`useMatches` only resolves *which* matches — pair it with
[useMatch](/docs/ui/hooks/use-match) to actually fetch one:

```tsx
const matches = useMatches({ sports: ["soccer"], status: ["upcoming"], limit: 1 })
const matchId = matches?.[0]?.id
const match = useMatch({ matchId })
```
