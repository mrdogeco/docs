## Installation

<InstallTabs name="use-live-match" />

Installing this pulls in three files: the hook itself, a browser SDK client
singleton (`getMrDogeClient`), and a Next.js route at
`app/api/mrdoge/token/route.ts` that mints short-lived tokens using
`@mrdoge/node` and your own `MRDOGE_ODDS_API_KEY` — the browser client never
sees the raw key.

## Usage

```tsx
import { useLiveMatch } from "@/hooks/use-live-match"

function Match({ matchId }: { matchId: string | undefined }) {
  const match = useLiveMatch({ matchId })

  if (match === undefined) return <p>Loading…</p>
  if (match === null) return <p>Couldn't load this match.</p>

  return <p>{match.homeTeam.name} {match.stats?.homeScore} — {match.stats?.awayScore} {match.awayTeam.name}</p>
}
```

Takes a single options object, like every real SDK method it wraps
(`matches.subscribe(params)`) — not positional arguments.

## Returns

`MatchDetail | null | undefined` — `undefined` while loading (or while
`matchId` is `undefined`), `null` if the subscribe failed (no fallback data
— an honest empty state beats a fake one), otherwise the current snapshot,
updated in place as `stats.upd` / `status.upd` events arrive.

## Why a hook, not just the component

[Match Card](/docs/ui/components/match-card) takes plain props — it doesn't
know where data comes from. `useLiveMatch` is the specific piece that
subscribes to a real match and feeds those props via
[`matchToMatchCardProps`](/docs/ui/components/match-card#use-with-the-mr-doge-sdk).
Use it as shown, or as a reference for wiring `matches.subscribe()` into
your own state management.
